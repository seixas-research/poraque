\chapter{Troubleshooting}
\label{ch:troubleshooting}

\section{The run stops immediately}

\begin{description}
  \item[``No material with a charge density found under \ldots''] Check \opt{data.path}: it is one
    directory holding one subdirectory per material, and a material is a
    directory with a density (\file{CHGCAR} or \file{fields.h5}) in it.
  \item[``Removed configuration section(s)'', or ``Replaced: \ldots''] The
    configuration is written for the schema that preceded 2026-10-13. The
    message names where each setting went
    (\opt{training.valid\_fraction} is \opt{training.validation.fraction},
    \opt{data.data\_paths} is \opt{data.path}, \opt{model.paw} is the
    \opt{ext2chg} section and its \opt{occupancies} block); or start again from
    \file{configs/train\_simple.yaml}. \file{EXTCAR} is always computed.
  \item[``Nothing to train''] The file has neither an \opt{ext2chg:} nor a
    \opt{chg2tau:} section. An operator is trained when its section is
    present.
  \item[``The PAW occupancies need each element's projector channels''] The
    occupancies are on (the default) and no \file{POTCAR} was found to lay the
    records out from. Give the data one with \opt{data.potcar\_dir}, or write
    \opt{occupancies: false} in the operator's section to train the grid alone.
  \item[``No pseudopotential file found and no \opt{--zval} given''] At
    inference, the structure directory has no \file{POTCAR}. Supply one, or pass
    \opt{--zval Pt=11}.
  \item[``Unknown key(s) in \ldots''] A typo in the YAML. The message lists
    the valid keys.
\end{description}

\section{The results look wrong}

\begin{description}
  \item[$R^2$ is negative] The model is worse than predicting the mean. Usually
    too few epochs, or a learning rate that diverged --- check the loss curve in
    \file{models/<name>/plots/}.
  \item[The electron count is far off] Nothing constrains it by default. A few
    per cent is normal; tens of per cent means the model is extrapolating,
    typically because the evaluation grid is far from the training resolution.
  \item[The numbers seem too good] Check whether anything was held out. With
    \opt{validation.fraction: 0} they are a training fit. The report's
    \emph{What these numbers do not show} section states this explicitly.
\end{description}

\section{Grids and shapes}

\begin{description}
  \item[``grid shape \ldots does not match the supplied shared grid''] Two
    fields of one material are on different meshes. All three must share a grid;
    read them with \opt{grid=} from the same source.
  \item[``Cannot batch mixed grid shapes''] Use the shape-bucketed loader
    (the training script does) or \opt{training.batch\_size: 1}.
  \item[A few negative voxels in \file{TAUCAR}] Band-limiting a strictly
    positive field with sharp core peaks rings slightly. It is an artifact of
    the downsampling, not of the data, and is why the pipeline uses a
    sign-tolerant $\operatorname{asinh}$ normalization.
\end{description}

\section{Devices}

\begin{description}
  \item[``CUDA was requested but \ldots''] A warning, not an error --- the run
    continues on CPU.
  \item[Training is slower on MPS than CPU] At small grids kernel-launch
    overhead dominates. The advantage grows with size: $2.2\times$ at $32^3$,
    $5.7\times$ at $64^3$.
  \item[Results differ slightly between devices] Expect $\sim10^{-6}$ relative
    on a single forward pass. Two \emph{independently trained} runs will differ
    much more, because optimization amplifies tiny differences --- that is not a
    bug.
\end{description}

\section{Reports}

\begin{description}
  \item[A \file{.tex} appears instead of a PDF] No \opt{latexmk} or
    \opt{pdflatex} on the path. The source is written so it can be compiled
    elsewhere.
  \item[Stray \file{.aux} or \file{.log} files] Should not happen: reports are
    built in a temporary directory that is deleted wholesale. If you see them,
    they came from compiling the guides by hand --- use \opt{make} in
    \file{latex/technical\_guide/} or \file{latex/user\_guide/}, which cleans up.
\end{description}
