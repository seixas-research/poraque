# Runtime POTCAR policy and VASP 6.6.1 benchmarking

**A valid VASP license is required to supply and use POTCAR files and VASP.**
Poraque supplies software only. It does not supply, generate, download, print,
bundle or redistribute PAW potential data or excerpts. The parser reads
explicit external files. The runner creates a symlink to an existing runtime
file; it never assembles or copies potential contents. Hashes identify inputs
but do not certify authenticity or license rights. Keep all potential files
and private VASP runtime outputs out of source control and distributions.

The previous fixed-directory loader is replaced by
`poraque.fields.vasp.user_paw.UserPawDataset.load(path, functional, element=None)`.
It requires a file, emits `PotcarLicenseWarning`, validates PAW tables/functional
matching, and detects source changes during/after parsing. An existing user
concatenation can be selected by unique element; it is never generated by
Poraque. `VaspBlochHarris(..., potcar_files=...)` takes that concatenation or a
species-to-file mapping. `--potcar` is mandatory for `poraque-bloch`.

Wheel content is restricted to code; source distributions have an explicit
code-only include list and POTCAR exclusions. `.gitignore` excludes POTCAR and
compressed/variant filenames. The repository audit found no tracked POTCAR
files. Tests requiring real PAW data run only with explicit external inputs:
`PORAQUE_TEST_POTCAR_H` and optionally `PORAQUE_TEST_POTCAR_BI`. No proprietary
PAW fixtures or snippets were added for testing. A distribution archive still
needs inspection by its publisher before release; no release is made here.

## Automated benchmark

Provide a manifest, following `manifest.example.json`. Every case supplies a
POSCAR/INCAR/KPOINTS directory and an explicit external, uncompressed POTCAR.
The case's potential must match its structure and the ext2chg model. For example:

```json
{"cases": [{"id": "material_001", "deck_directory": "/private/case_001",
            "potcar": "/licensed/case_001/POTCAR"}]}
```

```bash
python scripts/poraque_benchmark.py manifest.json \
  --models /private/models/ext2chg.poraque \
  --vasp-bin /home/leseixas/Codes/vasp/6.6.1/bin/vasp_std \
  --work-root /private/vasp_benchmark_runs --output summary.json \
  --threads 1 --timeout 600
```

The installed entry point is `poraque-benchmark`. `--launcher "mpiexec -n 4"`
selects a user-controlled MPI command, executed as an argument list, never via
a shell. SOC/noncollinear cases require explicit `--vasp-ncl` because vasp_std
cannot solve spinors. No VASP executable is bundled. Each case runs in a new
private directory outside source checkouts. Timeouts terminate its process group;
failed cases are reported and excluded from aggregate accuracy statistics.

The runner requires fixed-geometry SCF decks. It fixes NSW/IBRION, starts fresh,
uses matching explicit fine FFT grids, LASPH=True and no symmetry reduction,
and requests CHGCAR for optional diagnosis. It retains the supported common
ENCUT, NBANDS, XC, charge, spin and smearing settings. It records input/model
hashes, resources, timings, density processing and numerical residuals. Only a
completed VASP **6.6.1** output with explicit EDIFF convergence is a reference.
An energy line alone, OSZICAR F/E0, or reaching NELM is not convergence proof.
The automated matched benchmark currently requires PBE. The parser/solver can
accept user-provided LDA potentials, but PZ versus PW92 runtime correlation must
be matched explicitly before an LDA comparison can be accepted.

`read_vasp_reference` distinguishes:

| Quantity | Poraque comparison |
|---|---|
| VASP TOTEN / OSZICAR F | Harris free energy |
| OUTCAR energy without entropy | Harris internal energy |
| OUTCAR sigma->0 / OSZICAR E0 | Separate extrapolated estimate; never substituted for internal energy |

`--repair-density`, `--spin-average` and `--unpolarized-input` are explicit
approximations inherited from the production pipeline and logged. Neither
CHGCAR nor atomic reference occupancies replace ext2chg in the primary result.

Every comparison carries `within_chemical_accuracy`, the absolute error against
`CHEMICAL_ACCURACY_MEV_PER_ATOM` (43 meV/atom, `poraque.benchmarks.analysis`),
and the summary counts `within_chemical_accuracy` over the valid cases and
sets `all_within_chemical_accuracy`, which is `False` for a run with no valid
case. That flag is what a tracker should watch; the per-atom MAE, RMSE and
maximum are beside it.

## Error attribution and stationarity diagnostics

`--diagnose-scf-density` separately evaluates the Poraque Hamiltonian at VASP's
SCF grid/on-site records, then interpolates both fields and PAW records toward
the ML prediction. This gives the algebraic decomposition

```
ΔE_total = E_Poraque[ML] - E_VASP[SCF]
         = (E_Poraque[ML] - E_Poraque[SCF input])
           + (E_Poraque[SCF input] - E_VASP[SCF]).
```

The second term exposes backend/basis/grid/PAW implementation differences.
This diagnostic never changes the primary ML result. A grid/representation
mismatch fails explicitly. The noncollinear CHGCAR diagnostic reader remains
unimplemented and is reported unavailable; the main spinor solver is separate.

Raw SCF grids can contain tiny negative voxels or small electron-count drift.
The default diagnostic rejects such input instead of silently repairing it.
`--diagnostic-repair-scf` explicitly clips negative eigen-densities, normalizes
charge/magnetization and scales records, reporting all changes — through the
same `poraque.physics.density_repair` call that repairs the ML prediction, so
reference and prediction are corrected identically
(`reference_density_adjustment`: `raw_electrons`, `negative_charge_e` on the
eigen-densities, `charge_defect_e`, `clipped_electrons`, `factor`). That
reference is **no longer exactly stationary**, so interpolation cannot
establish the ideal Harris theorem. Report keys state this limitation.

For a common stationary functional and charge/magnetic constraint, writing
x=(rho,m,PAW occupancies) and δx=x_in-x_SCF gives

```
E_HF[x_in] - E_SCF = (1/2) δx^T K δx + O(||δx||^3).
```

There is no universal eV bound from a density percentage: K is system dependent,
metallic occupations and magnetic state changes can spoil the local smooth
expansion, and Harris is not generally an upper bound. Close densities in a
converged matching implementation may reach a meV/atom scale; the present
predictions need not. FFT aliasing/quadrature, cutoff errors, projector
interpolation, frozen-core/XC treatment, PAW normalization and reference offsets
can create residual errors even at SCF input. Missing one-center terms would
cause additional systematic errors; this PAW implementation includes them,
so they cannot simply be asserted to explain an observed discrepancy.

The analysis fits `E(lambda)-E(0)=a lambda+b lambda²` and also records the observed
logarithmic power. A nonzero linear coefficient, a poor fit, or a power far from
two flags stationarity/matching problems or a density outside the local regime.
The finite-range fits are diagnostics, not proofs of asymptotic order.

## Actual local results

`h2_results.json` records three **converged SCF** VASP 6.6.1 runs with the same
licensed runtime potential and shipped CHON ext2chg checkpoint. Structures
were periodic H2 in a 5-Angstrom cube, Gamma only, ENCUT=80 eV, 16^3 density
grid, Gaussian SIGMA=0.05 eV, scalar PBE/LASPH, EDIFF=1e-8. Model density repair
and spin averaging were explicitly enabled. Geometry, cutoff, vacuum and grid
are not converged for chemical accuracy; this is a narrow implementation audit.

| H-H distance (A) | VASP F (eV) | Harris F (eV) | ΔE (eV/cell) | Absolute error (meV/atom) |
|---:|---:|---:|---:|---:|
| 0.74 | -6.55861531 | -6.36567965 | +0.19293566 | 96.47 |
| 0.90 | -6.83111519 | -6.66246156 | +0.16865363 | 84.33 |
| 1.10 | -6.28826807 | -6.13153226 | +0.15673581 | 78.37 |

MAE=86.39 meV/atom; RMSE=86.72 meV/atom. All three errors are positive, but that
sample does not establish an upper-bound property. Poraque took 1.54–1.80 s
including preparation/model loading; VASP took 0.77–0.82 s. The current small
CPU runs demonstrate **no speedup**. They do not benchmark distributed scaling.

The explicit diagnostic repair changed SCF charge by factors 1.00011–1.00022;
raw negative charge was at most 3.8e-9 electrons. At these processed reference
inputs the residual backend offsets were 10.01, 1.51 and 11.97 meV/cell. The
remaining density/occupancy differences contributed 182.93, 167.15 and 144.76
meV/cell. Density L1 differences were 0.40–0.55 electrons. Observed interpolation
powers over lambda=0.125..1 were 2.04, 1.64 and 1.41. The reference adjustment,
nonzero linear fits and finite interval prevent clean quadratic attribution.

`native_validation.json` records the C correctness checks. A complete PAW
Harris evaluation with the native adapter differed from SciPy by 5e-14 eV,
well below the scientific discrepancies above. Native eigenpair residual was
1.4e-13 eV. This separates diagonalization roundoff from model/DFT errors.
Private OUTCAR/CHGCAR/runtime files and potential data are not in these artifacts.

The input-density double counting follows the [VASP Harris documentation](https://vasp.at/wiki/Harris-Foulkes_functional).


The complete relevant regression run passed **396 tests, with 16 skipped**.
The optional native MPI test was enabled, using explicit external licensed PAW
inputs for the PAW tests. A separate four-rank single-group run tested a true
2x2 BLACS grid with a 1.9e-14 eV maximum generalized residual.

## Matched CHON molecules (2026-10-18)

`chon_results.json` holds the first CHON run of the tripartite suite: H2, CH4,
NH3, H2O and CO (experimental gas-phase geometries, not relaxed), each in a
5 Angstrom periodic cube, Gamma only, ISPIN = 1, Gaussian SIGMA = 0.05 eV,
EDIFF = 1e-8, scalar PBE/LASPH, VASP 6.6.1, one thread, with the standard
`PAW_PBE` potentials of the CHON isolated-atom runs supplied as explicit
external concatenations kept outside the repository. Flags:
`--repair-density --spin-average --diagnose-scf-density
--diagnostic-repair-scf` (without the last, the SCF diagnostic of the H2 case
fails with "Spin charge density is not normalized to NELECT": the raw VASP
grid is off by ~1e-4 electrons). **ENCUT = 300 eV, below the ENMAX of C, N and O
(400 eV)**, because the dense solver refuses more than 2048 plane waves
(`max_basis`) and 400 eV in a 6 Angstrom cube needed 3887. VASP and Poraque use
the same cutoff, so the comparison is matched, but neither number is converged
and the cell is a 5 Angstrom cube around each molecule. Two ext2chg bundles were
run: `models/chon/chon_ext2paw_charge.poraque` and
`models/chonps/model_CHONPS.poraque`.

The error column is signed (Harris minus VASP) per atom; the density factor is
the normalization applied to the prediction (raw electron count 2.043, 2.011,
8.021 for the three valid cases). Interpolation powers at the SCF density were
2.31, 2.11 and 2.12; the reference was repaired, so these are not clean
quadratic attributions (see above).

**Seven of ten case-model pairs failed, all in the same way**, before any
energy: the Poraque side raised `Spin density matrix is not positive
semidefinite: require n>=|m|` in `physics/spin_xc.py` (`SpinDensityInput.validate`),
reached from `PawHarrisEvaluator._prepare`. The repaired valence density is
non-negative, but the exchange-correlation input is valence plus the POTCAR's
pseudo partial-core density, and that reconstructed core is slightly negative
in the vacuum (minimum -5.4e-5 in the evaluator's grid units for the CH4 case, giving a sum of
-4.9e-8 where the prediction was floored at zero). H2 has no core and passes;
only the CHONPS model on H2O happened to leave a vacuum density above the core's
negative lobes. VASP converges these cases (the VASP energies above are valid
references). No source was changed to make the cases pass; whether the check
should be applied with a tolerance, or the core clipped, is a decision for the
physics code. The summary statistics are therefore over two valid cases for
CHONPS (bias and MAE 20.8 meV/atom, RMSE 23.5, max 31.7, both within chemical
accuracy) and one for the CHON bundle (43.49 meV/atom, 0.49 meV above the
threshold, so `within_chemical_accuracy` is false and
`all_within_chemical_accuracy` is false). Two or one cases do not support a
statement about either model.

Backend offset at the SCF density was 0.4-0.7 meV/cell, an order of magnitude
below the H2 runs recorded above; the error is the predicted density and
records. Speedup (VASP time over Poraque time) was 0.17-0.19: no gain at these
sizes.
